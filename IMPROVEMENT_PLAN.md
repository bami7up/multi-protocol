**Основание:** аудит `AUDIT-2026-11-03.md`, ревизия `83342b0` + локальные изменения (`lib/`).

## 1. Цели и критерии успеха

### Цели

1. Убрать или резко сократить простой `443/tcp` при продлении сертификатов.
2. Исключить риск переполнения диска логами Xray/Node.
3. Не ломать Mihomo и старые клиенты необдуманным `minClientVer`.
4. Честно описать модель угроз CDN + Hysteria2 и дать оператору осознанный выбор.
5. Сделать отказ CDN-сертификата (526/525) видимым до жалоб пользователей.
6. Дать возможность использовать собственный self-steal сайт.
7. Гарантировать уникальность тега ноды во всех режимах, а не только в quick.
8. Проверить и, если возможно, убрать внешнюю зависимость XHTTP+REALITY.
9. Зафиксировать проверенную матрицу версий Panel/Node/Xray.
10. Усилить защиту CDN origin и документировать остаточные риски.

### Критерии успеха (через 1–2 релизных цикла)

- Продление сертификатов не приводит к ошибкам `443/tcp` (0 failed health-checks в окне продления).
- Свободное место на диске стабильно; рост логов ограничен политикой 50M×5 или эквивалентом.
- Mihomo и актуальный Xray-клиент подключаются; нет массовых `REALITY authentication failed`.
- В README есть явная матрица «CDN скрывает TCP / Hysteria2 остаётся прямой».
- Алерт по сертификату срабатывает минимум за 14 дней до истечения и при 526/525.
- Две ноды на одном домене не смешивают `injectHosts` и не перезаписывают друг друга.
- Есть зафиксированный результат теста XHTTP+REALITY с local target.
- В README нет расхождения между заявленной и проверенной версией Xray/Node.

## 3. Этап 0 — quick wins

### QW-1. `minClientVer`: сделать явную настройку и объяснить компромисс

- **Проблема:** `0.0.0` зашит; причина неочевидна; `26.3.27` ломает Mihomo.
- **Действие:** оставить `0.0.0` дефолтом; добавить документированный параметр
  «минимальная версия клиента»; в README указать: значения выше `1.8.2` могут
  отсечь Mihomo, проверяйте матрицу клиентов.
- **Критерий приёмки:** в README и шаблоне описано, как менять значение; тест с
  Mihomo и Xray-клиентом проходит; значение по умолчанию не меняется.
- **Риск/сложность:** низкая; главное — не ужесточать дефолт без теста.

### QW-2. Явная модель угроз CDN + Hysteria2

- **Проблема:** README упоминает ограничение, но оно теряется; пользователи ждут
  «CDN скрывает IP».
- **Действие:** добавить в README короткий раздел/таблицу:
  - CDN скрывает TCP-маршрут VLESS/CDN;
  - Hysteria2 (`443/udp`) остаётся прямой, IP виден через DNS и UDP;
  - если скрытие IP обязательно — отключить Hysteria2 или вынести на отдельный
    IP/хост; port hopping не скрывает IP.
- **Критерий приёмки:** раздел есть в README и в выводе мастера/сводке; нет
  формулировок «CDN полностью скрывает ноду».
- **Риск/сложность:** низкая, только документация/UX.

### QW-3. Проверить и зафиксировать политику логов Xray

- **Проблема:** в репозитории нет logrotate; `/var/log/xray/current` внутри
  контейнера может не покрываться Docker-ротацией.
- **Действие:** выяснить, пишет ли конкретный `remnawave/node` в stdout или в файл.
  Если stdout — зафиксировать, что работает Docker `max-size=50m/max-file=5`.
  Если файл — смонтировать `/var/log/xray` на host и добавить logrotate `50M × 5`
  (compress); либо переключить Xray на stdout, если это допустимо образом.
- **Критерий приёмки:** 24-часовой soak-тест не даёт роста диска выше заданного
  порога; `logrotate -d` не показывает ошибок; после ротации Xray продолжает писать.
- **Риск/сложность:** низкая/средняя; `copytruncate` может терять строки, volume
  добавляет точку отказа.

## 4. Этап 1 — надёжность сертификатов и наблюдаемость

### P1-1. DNS-01 для всех сертификатов, где есть Cloudflare-токен

- **Проблема:** HTTP-01 останавливает Caddy и рвёт `443/tcp`.
- **Действие:** использовать `dns_cf` для `SELF_STEAL_HOST` и `HY_HOST` по аналогии
  с CDN; HTTP-01 оставить fallback для режима без Cloudflare. В README указать:
  «HTTP-01 = короткий простой `443/tcp` при продлении; DNS-01 = без простоя».
- **Критерий приёмки:** тестовое продление с DNS-01 не вызывает падения health-check
  на `443/tcp`; сертификаты валидны; при отсутствии токена установщик явно
  предупреждает о возможном простое.
- **Риск/сложность:** средняя; нужны права `Zone:Read` + `DNS:Edit`, DNS-пропагация,
  ротация токена. Есть rate limits ACME — тестировать на staging.

### P1-2. Периодический selfcheck: сертификаты, CDN 526/525, TLS origin, listeners

- **Проблема:** health-check только при установке; после сбоя продления CDN
  возвращает 526/525 без понятной диагностики.
- **Действие:** отдельный ops-скрипт/таймер (systemd timer или cron), который:
  - проверяет срок сертификатов в `/etc/remna-certs/*`;
  - делает `openssl s_client` к `127.0.0.1:9444` с `-servername CDN_HOST`;
  - проверяет HTTP-ответ CDN-хоста (526/525/530);
  - проверяет listeners `443/tcp`, `443/udp`, `10443–10448`;
  - отправляет алерт при <14 днях и при 526/525.
- **Критерий приёмки:** синтетический просроченный сертификат/подмена CDN-ответа
  вызывает алерт; ложных срабатываний нет; токены не хранятся в скрипте.
- **Риск/сложность:** средняя; нужны пути к сертификатам и канал алертов.

### P1-3. Политика логов как эксплуатационный стандарт

- **Проблема:** QW-3 может остаться разовым решением.
- **Действие:** зафиксировать в README/runbook: где логи, кто ротирует, какой лимит,
  что делать при диск-алерте; добавить проверку свободного места в selfcheck.
- **Критерий приёмки:** runbook и алерт по диску; после инцидента понятно, какой
  файл/контейнер заполнил диск.
- **Риск/сложность:** низкая.

## 5. Этап 2 — multi-node, XHTTP+REALITY, CDN hardening

### P2-1. Уникальный `NODE_TAG` во всех режимах

- **Проблема:** в manual/advanced тег зависит от `PREFIX`/хоста; при дефолтном `usa`
  вторая нода получает тот же тег; шаблон по умолчанию использует `USA`.
- **Действие:**
  - генерировать тег из стабильного идентификатора ноды (host + короткий суффикс
    IP/random) при первом запуске;
  - сохранять тег в env и не менять при повторном запуске;
  - для ручного шаблона требовать замены `USA` в `balancerTag`/`injectHosts` или
    выдавать готовый `Xray_template.json` с тегом ноды;
  - проверять конфликт тегов в панели и предупреждать.
- **Критерий приёмки:** две ноды на одном домене с разными адресами не смешивают
  `injectHosts`; подписки содержат только хосты своей ноды; повторный запуск не
  меняет тег.
- **Риск/сложность:** средняя; смена тега на работающей ноде ломает подписки —
  фиксировать тег при первом запуске и документировать миграцию.

### P2-2. Лабораторный тест XHTTP+REALITY с local self-steal target

- **Проблема:** внешний `target: www.gstatic.com:443` — зависимость и потенциальный
  forwarder для неаутентифицированного трафика.
- **Действие:** на стенде с Xray `v26.10.31` и Caddy проверить:
  - `REALITY_XHTTP` с `target: 127.0.0.1:9443`, `serverNames: [SELF_STEAL_HOST]`;
  - большие загрузки, стриминг, несколько одновременных сессий;
  - поведение при неверном shortId (fallback на self-steal).
  Если работает — перейти на local target; если нет — оставить внешний, но добавить
  `limitFallbackUpload/Download` и записать это как технический долг.
- **Критерий приёмки:** матрица «local/external target × Xray version × клиент»
  с результатами; решение зафиксировано в README/ADR.
- **Риск/сложность:** средняя; нужен стенд и проверка больших потоков.

### P2-3. Усиление CDN origin

- **Проблема:** origin достижим по IP+SNI; CDN не скрывает Hysteria2.
- **Действие:** рекомендовать и по возможности включить по умолчанию один из
  вариантов: Cloudflare Authenticated Origin Pulls (mTLS) + `client_auth` в Caddy
  или allowlist Cloudflare IP на `443/tcp`. Явно указать, что это не скрывает
  Hysteria2.
- **Критерий приёмки:** прямой запрос к origin без клиентского сертификата/из
  не-Cloudflare IP не проходит; CDN-маршрут работает; есть процедура отката.
- **Риск/сложность:** средняя; mTLS ломает прямые подключения, allowlist нужно
  поддерживать при смене диапазонов Cloudflare.

### P2-4. Режим «свой сайт» / `none`

- **Проблема:** всегда ставится тема или скачивается URL; нет способа оставить
  собственный сайт.
- **Действие:** добавить вариант «не устанавливать шаблон»: не трогать
  `SELF_STEAL_ROOT`, проверить наличие `index.html`, предупредить, если пусто.
  Либо отдельный `SELF_STEAL_ROOT` для своего контента.
- **Критерий приёмки:** существующие файлы не затираются; пустая директория даёт
  явное предупреждение; Caddy продолжает отдавать сайт.
- **Риск/сложность:** низкая; пустой сайт ухудшает маскировку — предупреждение
  обязательно.

### P3-3. Runbooks и диагностика

- **Критерий приёмки:** каждый инцидент из аудита имеет пошаговую диагностику.
- **Риск/сложность:** низкая.

## 8. План проверки и отката

### Проверка

1. **ACME:** staging-сертификат + продление с DNS-01; параллельный health-check
   `443/tcp` (Vision/XHTTP/CDN) и `443/udp` (Hysteria2).
2. **Логи:** 24-часовой soak, `logrotate -d`, проверка свободного места, ротация.
3. **minClientVer:** подключение Xray-клиента и Mihomo; проверка `auth failed`.
4. **Selfcheck:** искусственно просроченный сертификат/подмена ответа CDN; алерт.
5. **Multi-node:** две ноды с разными адресами/тегами; проверка подписок и хостов.
6. **XHTTP:** local/external target; большие загрузки, стриминг, конкурентность.
7. **CDN origin:** прямой запрос без mTLS/из чужого IP; CDN-маршрут; откат.
8. **Own site:** существующий `index.html` не затёрт; пустая директория — warning.

### Откат

- ACME: вернуть HTTP-01 и pre/post-hooks; держать старый сертификат до успешного
  продления.
- Логи: вернуть stdout/предыдущий logrotate; не удалять активные файлы.
- minClientVer: вернуть `0.0.0`.
- Multi-node: зафиксировать старый `NODE_TAG`/профиль; не менять тег на работающей
  ноде без плана миграции.
- XHTTP: оставить внешний target как fallback, пока local не подтверждён.
- CDN hardening: отключить mTLS/allowlist, вернуть предыдущий Caddyfile.

## 9. Что не входит в план

- Переписывание Remnawave Panel/Node и их внутреннего API.
- Замена Caddy L4 на Nginx stream «ради интереса» — только как отдельный
  архитектурный эксперимент, не как обязательный шаг.
- Полная замена acme.sh на встроенный ACME Caddy — возможна, но это отдельный
  проект с другим профилем рисков.
- Автоматическое создание пользователей/подписок.
- Изменения в `remnanode-setup.sh` в рамках этого плана: план описывает **что**
  изменить, а не готовые патчи.

2. Проверить, куда пишет Xray, и закрыть риск диска.
3. Перевести ACME на DNS-01 там, где есть Cloudflare; иначе — явно предупредить
   о простое.
4. Добавить selfcheck сертификатов/CDN/listeners.
5. Закрепить уникальный `NODE_TAG` и проверить две ноды.
6. Провести тест XHTTP+REALITY local target; принять решение.
7. Включить/рекомендовать CDN origin hardening.
8. Добавить режим «свой сайт».
9. Обновить матрицу версий и архитектур.
10. Дописать runbooks и провести ретроспективу по метрикам.

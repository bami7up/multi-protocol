# Политика безопасности

Установщик `remnanode-setup.sh` работает от root, настраивает публичный периметр (Caddy L4 на `443/tcp` и `443/udp`, UFW), обращается с `SECRET_KEY` ноды, токеном Cloudflare и ключами сертификатов. Поэтому сообщения об уязвимостях лучше не публиковать в открытом виде.

## Как сообщить об уязвимости

1. Включите в репозитории **private vulnerability reporting** (Settings → Code security) и отправьте отчёт через GitHub Security Advisories — приватный репорт виден только мейнтейнеру.
2. Если приватный канал недоступен, откройте обычный issue **без деталей эксплуатации** и попросите приватный контакт. Не прикладывайте токены, ключи, UUID и адреса инфраструктуры.

## Что полезно приложить

- коммит/версию репозитория и вывод `bash remnanode-setup.sh --help`;
- ОС, архитектуру и версии из финального блока установщика (Caddy, caddy-l4, Go, образ ноды);
- минимальные шаги воспроизведения и **очищенный** лог `/var/log/remnanode-setup-*.log` — из него нужно вырезать адреса и домены;
- ожидаемое и фактическое поведение.

## Что считается ошибкой безопасности

- утечка `SECRET_KEY`, токена Cloudflare или ключей сертификатов — в лог, в `ps`, в файл с неверными правами, в историю команд;
- выполнение чужого кода: подмена шаблонов фасада или профиля, обход проверки SHA256 архива Go, подмена источников установки;
- доступ к Node API или к панели в обход firewall;
- обход TLS-политики Caddy: согласование TLS 1.0/1.1, подмена сертификата CDN-хоста, отключение HSTS;
- инъекция в генерируемые конфиги (Caddyfile, `Multiselect.json`, `.env`) через переменные окружения, ответы на вопросы или имена доменов.

## Что не считается ошибкой безопасности

- необходимость знать UUID/пароль клиента, чтобы подключиться, — это не доступ к инфраструктуре;
- прямая достижимость origin по SNI в CDN-схеме: это задокументированное ограничение (раздел README «VLESS за CDN → Ограничения») вместе со способами защиты;
- уязвимости в сторонних компонентах (Caddy, caddy-l4, Xray-core, Remnawave Panel/Node) — сообщайте их апстримам; сюда стоит написать, если установщик конфигурирует их небезопасно.

## Поддерживаемые версии

Исправления вносятся в `main`. Версии компонентов заданы пинами (`GO_VERSION`, `CADDY_VERSION`, `XCADDY_VERSION`, `CADDY_L4_VERSION`, `NODE_IMAGE`) и проверяются в CI; обновиться — значит повторить запуск установщика из свежего коммита.
